# v2026.1012.0-mikoshi.3

Upstream `paperclipai` **2026.1012.0** (tag `v2026.1012.0`) plus six fixes from the mikoshi fork (five server, one shared validator). Not published to npm.

## Install

```sh
npm install -g https://github.com/overcuriousity/paperclip/releases/download/v2026.1012.0-mikoshi.3/paperclipai-2026.1012.0-mikoshi.3.tgz
```

## Packaging

- `paperclipai-2026.1012.0-mikoshi.3.tgz` is the CLI. It depends on the forked server by the URL of its release asset, not by a registry version:
  `@paperclipai/server`: `https://github.com/overcuriousity/paperclip/releases/download/v2026.1012.0-mikoshi.3/paperclipai-server-2026.1012.0-mikoshi.3.tgz`
- `paperclipai-server-2026.1012.0-mikoshi.3.tgz` is the forked `@paperclipai/server`, built from branch `mikoshi`. From this release it also bundles the fork's `@paperclipai/shared` build under `node_modules/@paperclipai/shared` (still version `2026.1012.0`), because the MIK-743 fix lives in the shared request validators. The server resolves that nested copy; other packages keep the upstream shared.
- All other `@paperclipai/*` dependencies are the unchanged upstream packages. They are pinned to exactly `2026.1012.0` and resolve from the npm registry.
- `SHA256SUMS` lists the checksums of both tarballs.
- Build: `scripts/mikoshi-release.sh <version>`, run by `.github/workflows/mikoshi.yml` (workflow_dispatch with `release`).
- **Built locally, CI unavailable.** GitHub Actions was disabled for the fork when this release was cut, so `scripts/mikoshi-release.sh` and the workflow's typecheck, test and smoke-install steps were run by hand on hermes (Paperclip run `6f608579-de10-48e7-afd7-95d2dd56a1fd`, MIK-744) and the release was created with `gh release create --prerelease`.

## Changes on top of 2026.1012.0

- **MIK-268**: re-admit reassignment handoff wakes lost to the cleanup race. A reassignment could park the new assignee's wake on the stopped run's ownership blocker, and nothing re-admitted it. Upstream reports: #13532, #14537, #15138, #14973.
- **MIK-30**: do not create a board-only replay hold for a run that the stale-queued-run gate cancelled before it started.
- **MIK-137**: record a controller lease loss as `failed / controller_lease_lost` with a conversation continuation and a process-loss retry, instead of `cancelled`, which parked the issue `blocked` with no wake.
- **MIK-288**: do not create a board-only replay hold for a run the queue cancelled before it started (`issue_assignee_changed`, `issue_dependencies_blocked`, `issue_terminal_status`, or any stale-queued-run-gate cancel, with no `startedAt` and no `processPid`). A pre-dispatch review wait (`issue_continuation_waiting_on_review`) keeps upstream's evidence check.
- **MIK-684**: do not create a reconciliation hold for a disposition-repair run that the dispatch gate cancelled before it started (`legacy_disposition_repair_suppressed`, no pid). Such a hold silently deferred an accepted card and a board comment.
- **MIK-743**: `multilineTextSchema` (document, comment, description and summary bodies) no longer turns a literal backslash-n or backslash-r into a line break when the text already contains a real line break, so shell blocks in multi-line bodies round-trip byte-exact. A single-line value still converts (upstream's double-escape rescue). Supersedes `v2026.1012.0-mikoshi.2`, which lacks MIK-684 and MIK-743.
